# orders-platform

Generated by FastAPI Architect (design engine v2.0) from the `orders-platform` contract (digest `f16d2acd4f57`); style **hexagonal**.

## Why this structure

- ports and adapters for the integrating modules: 2 outbound integrations, 1 high-criticality integration(s), contract tests required; use cases must not depend on the client libraries

Rejected alternatives:

- `microservices`: independent deployment is not stated; network partitions, distributed consistency and per-service operations are paid for only when deployment independence is required
- `layered`: a single package by layer blurs ownership once several capabilities share services and repositories

## Run

```
uv sync                      # or: pip install -e . --group dev
uv run uvicorn orders_platform.main:app --reload
uv run pytest -q
uv run ruff check .
```

Settings come from environment variables prefixed `ORDERS_PLATFORM_` (see `.env.example`; no secret has a default). `.audit-fastapi.json` declares the design decisions the auditor should respect (`python3 scripts/audit_fastapi.py .` from the plugin repository).

## Database and migrations

Tables are created by Alembic only (`create_all` is never called). Point `ORDERS_PLATFORM_DATABASE_URL` at a database you own,
then:

```
uv run alembic upgrade head      # apply the migrations (the first one is generated from the contract)
uv run alembic current           # show the applied revision
uv run alembic downgrade base    # remove the schema again
```

The test suite needs `DATABASE_URL` set to an **empty, disposable** database: it refuses a database that already has
tables, applies the migrations, truncates the tables after every test, checks that the migrated schema matches the
models (`compare_metadata` is empty), exercises up/down, and downgrades at the end.

## Tenants and API keys

`ORDERS_PLATFORM_API_KEYS` is a JSON object mapping each API key to the tenant it belongs to. A request to
`/api/v1/tenants/{tenant_id}/...` is accepted only when the key presented in `X-API-Key` is bound to that tenant
(403 otherwise); every repository call is scoped by that tenant id. This is authentication plus tenant membership.
It is **not** resource-level authorization and it is **not** row-level security: the generated isolation is
application scoping plus composite foreign keys between tenant tables.
