# team-notes

Generated by FastAPI Architect (design engine v2.0) from the `team-notes` contract (digest `b6d1af62ff91`); style **layered**.

## Why this structure

- 1 module(s), 2 entities, team of 3, small scope: one package by layer is the cheapest structure that still separates transport, use cases and persistence

Rejected alternatives:

- `microservices`: independent deployment is not stated; network partitions, distributed consistency and per-service operations are paid for only when deployment independence is required
- `hexagonal`: 0 outbound integration(s) and no high-criticality dependency: ports and adapters would add indirection without a second implementation to protect
- `modular_monolith`: fewer than three modules and a small team: module boundaries can be introduced when a second capability arrives (the layout keeps one package per layer that maps onto modules later)

## Identity (OIDC)

Requests carry `Authorization: Bearer <token>` issued by `https://login.example.com/` for audience `team-notes-api`. The token is
verified in `core/security.py`: algorithm in RS256 (nothing symmetric, nothing unsigned), signature
against the provider's JWKS (`TEAM_NOTES_OIDC_JWKS_URL`, https only, cached 300 s, refreshed once per unknown key
id), issuer, audience, `exp`/`nbf`/`iat` with 30 s leeway. The principal is built from verified claims only:
`sub`, `roles`, `workspace_id` (the tenant; the path parameter must match it, 403 otherwise).
A provider that cannot be reached is 503, never 401. Tests sign their own tokens and pass the public key as a static
JWKS (`oidc_jwks_json`), which the application accepts only when `TEAM_NOTES_ENVIRONMENT=test`.

## Authorization (model `roles_and_ownership`)

Roles come with the identity (the token). Each route carries the principal admitted
for its operation (`CanCreate`, `CanGet`, ...); an operation with a role list refuses, with 403, a principal without one of
them:

- `create`: admin, editor
- `update`: admin, editor
- `delete`: admin, editor

Owned entities (`notes.Note`) record the creating principal in `owner_id` (never taken from the request). Visibility is
**tenant**: every member of the tenant reads them; only the owner (or an admin) updates or deletes them, 403 otherwise.
Admin roles: admin. The checks live in the service and the repository (`core/authz.py`), not in the router.
